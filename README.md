# insomnia-headless-core-stub

This Insomnia collection provides importable templates for using the headless core stub to test a CRI. It comprises a
request collection and a corresponding base environment which provides and generates the necessary information (API
hosts etc).

## Sources

Information from the following documents was used to generate this collection:

- [CRI OAuth Flow](https://govukverify.atlassian.net/wiki/spaces/OJ/pages/4202332233/CRI+OAuth+Flow)
- [Headless core stub](https://govukverify.atlassian.net/wiki/spaces/OJ/pages/5324636169/Using+the+Headless+Core+Stub)

## Prerequisites

### GDS VPN

Some requests in this collection require you to be on the GDS VPN.

### Insomnia plugins

#### [insomnia-plugin-aws-sso](https://insomnia.rest/plugins/insomnia-plugin-aws-sso)

This plugin is used to make requests to API Gateway endpoints that are protected with AWS sigv4, using short-lived AWS
SSO sessions rather than long-lived credentials.

Once installed, make sure you have an SSO profile for the relevant account:

```sh
# create an SSO profile with an interactive tool
aws configure sso
```

You will then need to create a session with that SSO profile in the command line before making requests:

```sh
aws sso login --profile=my-profile-name
```

The profile name should be configured in the environment; see below for more information.

#### [insomnia-plugin-jwtcreator](https://insomnia.rest/plugins/insomnia-plugin-jwtcreator)

This plugin generates JWTs given the relevant information (headers, claims etc). This is necessary as the token endpoint
expects a JWT.

  </tr>

##### Converting the private JWK to PEM format

The script in the `get-pem-key` subdirectory can be used to generate a PEM key. Put the key in a `key.json` file, and
run `npm run get-pem` in the directory. This should return the correct JSON object.

## Usage

Once configured, the full CRI flow can be completed by firing the requests in order. This can be done manually, or by
choosing to run the collection in the Insomnia UI.

### Session initiation

#### Core stub - start

Creates a JWT representing the client's intent to create a session in the CRI.

#### Private - OAuth - Create session

Initiates the user journey in the CRI by creating session and person identity entries in DynamoDB.

#### [CRI journey]

At this point, the CRI APIs should be used to complete the journey. This is CRI-dependent, but the collection includes
examples for the Check HMRC and Address CRIs.

#### Private - OAuth - Get authorization code

Gets the authorization code which can be used with the public API to request an access token for VC retrieval.

#### Public - OAuth - Get access token

Generates an access token that can be used to get a VC.

#### Public - CRI - Get VC

Calls the CRI-specific function that validates whether the journey was successful and returns a VC.
